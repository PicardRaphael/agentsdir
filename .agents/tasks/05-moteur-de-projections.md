# 05 — Moteur de projections

Dépend de : 04

## Problème

Le cœur différenciant : matérialiser `CLAUDE.md` et `.claude/{rules,skills,agents}` depuis la source de vérité, en symlinks quand c'est possible, en copies suivies sinon.

## Fichiers

- `src/core/projections.ts` + tests couvrant LES DEUX modes

## Critères d'acceptation

- Mode `symlink` : liens relatifs (`CLAUDE.md → AGENTS.md`, `.claude/rules → ../.agents/rules`, etc.), vérification post-création que git les indexera en mode 120000.
- Mode `copy` : chaque projection est une copie de la source précédée d'un en-tête de fichier généré (« GENERATED by agentsdir — edit the source in .agents/ and run `agentsdir sync` ») ; son empreinte sha256 est enregistrée dans `[projections.hashes]` du manifeste. Pour `.claude/rules|skills|agents` (répertoires), copie récursive avec en-tête sur les fichiers Markdown uniquement.
- Le choix du mode vient du manifeste (posé par `init` d'après `detectSymlinkSupport`), jamais recalculé en silence — `doctor` propose la bascule, l'utilisateur décide.
- API consommée par `init`, `sync` et `check` : `project(sources) → écritures`, `verify(sources) → liste de dérives` (copie modifiée à la main, symlink remplacé par une copie, projection manquante, en-tête retiré).
- `CLAUDE.md` en mode copie contient l'import `@AGENTS.md` suivi de l'en-tête généré — pas une copie du contenu (une seule source lue par Claude Code, deux mécanismes possibles : symlink ou import).

## Notes d'implémentation

Décision à trancher au moment de l'implémentation et à documenter dans `docs/architecture.md` : en mode copie, `CLAUDE.md` par import `@AGENTS.md` (léger, mais dépend du support des imports par Claude Code) ou par copie complète avec en-tête (lourd mais autonome). Prototype rapide sur les deux, choisir, documenter.
