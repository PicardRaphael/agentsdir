# Hook quality rubric

Criteria marked ▣ are enforced mechanically by `agentsdir check` or by
the generator; the others belong to the critique pass (step 4).

## ▣ Mechanical

- ▣ Portable Node script, no dependency, reading one JSON payload on
  stdin; stdout empty or a single JSON object starting with `{`.
- ▣ Registered identically on every enabled harness by the generator
  (`node .agents/hooks/<file>` everywhere); regenerated by `sync`.
- ▣ Event known to the matrix (unknown events are refused with exit 2).

## Critique pass

- Event coherent with the intent: prevent → blocking event (PreToolUse,
  UserPromptSubmit, Stop) + exit 2; react → PostToolUse and kin, which
  cancel nothing.
- Fail-open or fail-closed chosen explicitly at the interview and
  documented as a comment in the script.
- A hook is NOT a security boundary: a hard ban lives in the harness
  permissions — refuse to create a hook for it.
- Stop hooks check stop_hook_active before acting (loop guard).
- Timeout adapted to the real work; long work is async, never blocking.
- A manual test is provided: `echo '<json>' | node .agents/hooks/<file>`.
