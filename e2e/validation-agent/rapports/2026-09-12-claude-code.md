# Validation par un agent réel — Claude Code, 12 septembre 2026

Première exécution du scénario de [../prompt.md](../prompt.md).

## Conditions

| Élément | Valeur |
| --- | --- |
| Harness | Claude Code 2.1.269 |
| Modèles | `claude-sonnet-5` pour toutes les sondes ; `claude-opus-5` pour la première, abandonné (même verdict, coût quarante fois supérieur) |
| CLI | agentsdir 1.0.0, `dist/cli.js` construit sur place |
| Machine | Windows 11, mode développeur actif — les symlinks fonctionnent |
| Terrain 1 | dépôt neuf, mode **symlink** (détecté), puis un second dépôt neuf en mode **copie** (forcé par `--mode copy`) |
| Terrain 2 | clone `--depth 1` d'un dépôt réel de 38 skills, `.agents/` peuplé, `.claude/{rules,skills,agents}` déjà en symlinks, `CLAUDE.md` déjà un lien, pas de `.agents.toml` |

Environnement non hermétique, assumé : la configuration utilisateur
(`~/.claude/`) est chargée en plus de celle du dépôt, et `--tools ""` ne retire
pas les serveurs MCP. Seuls les noms créés pour l'occasion — `demo-flow`,
`demo-reviewer`, `zorglub` — servent de preuve.

## Preuves

### 1 et 2 — découverte, par le message `system/init`

Mode symlink, dépôt neuf :

```
slash_commands (filtrés) : ["create-agent","create-hook","create-rule","create-skill","demo-flow","setup-context"]
agents                   : ["claude","demo-reviewer","Explore","general-purpose","Plan","statusline-setup"]
```

Mode copie, même montage, **avant correctif** :

```
slash_commands (filtrés) : ["create-agent","create-hook","create-rule","create-skill","demo-flow","setup-context"]
agents                   : ["claude","Explore","general-purpose","Plan","statusline-setup"]
```

`demo-reviewer` a disparu. Le fichier était pourtant bien projeté dans
`.claude/agents/demo-reviewer.md`, et `check` était vert.

L'invocation `/demo-flow` a été rejouée hors de Git Bash (piège du `/` initial),
dans les deux modes. Chaque fois, la session a cité le corps du `SKILL.md` —
« State in one or two sentences what this skill delivers and for whom. »,
« Replace every placeholder line of this template before committing. » — sans
disposer du moindre outil de lecture, et en mode copie elle a même nommé le
chemin `.claude/skills/demo-flow/SKILL.md` : le contenu était donc bien injecté
par l'invocation, dans un mode comme dans l'autre.

### 3 — la cause : l'en-tête généré passait devant le frontmatter

En mode copie, chaque projection Markdown était écrite ainsi :

```markdown
<!-- GENERATED by agentsdir — edit the source in .agents/ and run `agentsdir sync`. -->

---
name: demo-reviewer
...
```

Un harness ne parse le frontmatter que s'il commence au premier octet du
fichier. Conséquences mesurées : un sous-agent n'est pas découvert du tout ; un
skill l'est encore (par son nom de dossier) mais perd ses métadonnées — sa
description devient le commentaire, et `disable-model-invocation: true` est
ignoré, donc le skill est injecté dans le contexte de chaque session alors qu'il
devait en être absent.

Le dépôt agentsdir lui-même est en mode copie : la session qui a mené cette
validation listait ses propres méta-skills sous la description
`<!-- GENERATED by agentsdir — edit the source in .agents/ ... -->`. Le défaut
était donc en production dans le dépôt de référence, invisible pour `check`.

**Correctif** : `src/core/projections.ts`, fonction `decorateMarkdown` — une
source qui ouvre sur un bloc de frontmatter le garde en tête et reçoit l'en-tête
juste après. Preuve par mutation dans le message de commit ; ligne ajoutée au
tableau des gardes de [TESTING.md](../../../TESTING.md).

**Revérification par un agent réel, après correctif** (mode copie, même dépôt,
après `sync`) :

```
agents            : ["claude","demo-reviewer","Explore","general-purpose","Plan","statusline-setup"]
demo-flow présent : true
```

Et sur le dépôt agentsdir lui-même, à la question « le skill `create-agent`
figure-t-il dans la liste des skills disponibles fournie par ton contexte ? » :
**`ABSENT`** — la réponse attendue, `disable-model-invocation: true` étant enfin
lu.

### 4 — le hook

```json
{"type":"system","subtype":"hook_started","hook_name":"PreToolUse:Bash","hook_event":"PreToolUse"}
{"type":"system","subtype":"hook_response","hook_name":"PreToolUse:Bash","stderr":"blocked by the demo PreToolUse hook: command contains forbidden\n","exit_code":2,"outcome":"error"}
{"type":"user","message":{"content":[{"type":"tool_result","content":"PreToolUse:Bash hook error: [node .agents/hooks/pretooluse-hook.mjs]: blocked by the demo PreToolUse hook: command contains forbidden\n","is_error":true}]}}
```

La session a conclu d'elle-même : « La commande a été bloquée par un hook de
sécurité (PreToolUse) configuré dans ce dépôt de démo […] elle n'a donc jamais
été exécutée par le shell. »

Le hook enregistré sans `matcher` s'applique à tout outil, et `check` reste vert
après l'édition de son corps : le contenu du hook appartient bien à
l'utilisateur.

### 5 — `AGENTS.md` lu à travers le lien

Question posée sans aucun outil, réponse intégrale :

```
1) `npm run zorglub:test`
2) `.agents/rules/tasks.md`
```

`zorglub` n'existe nulle part ailleurs que dans le `AGENTS.md` généré par
`init`. Le lien `CLAUDE.md → AGENTS.md` est donc bien suivi, et le bloc géré
`rules-index` bien lu. Nuance : l'index est lu, pas les règles elles-mêmes —
c'est la conception (lecture à la demande), pas un défaut.

### 6 — les messages des générateurs

Sorties soumises telles quelles à une session sans dépôt ni documentation.
Verdict rendu : « sais-tu quoi faire ensuite ? » — **non** pour `add skill`,
**non** pour `add agent`, **non** pour `add hook`. Manquent, dans l'ordre de
gravité rapporté : l'étape suivante explicite, la liste des emplacements à
compléter dans le fichier créé, et — pour `add hook` — la nature exacte de
l'écriture dans trois fichiers de configuration partagés, tous annoncés
« created ». Le message `stdin is not a TTY — using template defaults.` ne
nomme aucun moyen de donner de vraies réponses.

### 9 — terrain réel

`doctor` avant `init` : diagnostic juste (« not initialized », workflow CI
absent, `.gitattributes` sans `eol=lf`), sans rien écrire.

`init --dry-run` puis `init` : `keep` sur `CLAUDE.md`, `.claude/rules`,
`.claude/skills`, `.claude/agents` et `skills-lock.json` — les projections
préexistantes, déjà conformes, sont reconnues et préservées. **Rien n'a été
détruit.**

`check` ensuite : **192 violations, code de sortie 1**. Les 38 skills du dépôt
ne portent pas le frontmatter étendu qu'exige le contrat (`display-name`,
`short-description`, `color`, `icon`, `default-prompt`), et un sous-agent nommé
`Snipper` est refusé par `agent-name-spec`. Or `init` venait d'écrire le
workflow CI qui exécute `check` : le prochain commit casse la CI, et rien dans
la sortie d'`init` ne le laissait prévoir.

Observation à verser au dossier `migrate` : Claude Code découvre parfaitement le
sous-agent `Snipper`, que notre contrat refuse. Le contrat est ici plus strict
que le harness — défendable, mais c'est un choix à assumer explicitement le jour
où `migrate` existera.

Découverte après `init`, sonde `system/init` : 96 slash commands, dont les cinq
méta-skills installés par `init` et les skills préexistants ; le sous-agent
préexistant toujours là. **`init` sur une configuration vivante ne casse pas la
découverte.**
